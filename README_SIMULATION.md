# LE-PPO 仿真代码（Python / PyTorch）

依据《尤子硕-1202.docx》的第三、四节，提供统计物理层、无线供能与 MEC 环境、LE-PPO 训练、对照评估和绘图。**这是可运行的研究原型，不是已经验证论文性能结论的实验结果。** 文档没有完整仿真参数，下面给出的取值均为本实现选择，不能当作文档原有实验参数。

## 1. 快速运行

建议 Python 3.10–3.12，CPU 即可。当前云机器已配置 `/workspace/LEPPO/.venv`，可以直接用 `.venv/bin/python` 运行。新机器可执行：

```bash
cd /workspace/LEPPO  # 下载后改成实际项目目录
python3 -m venv .venv
source .venv/bin/activate
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install 'numpy>=1.26,<3' 'matplotlib>=3.8,<4'
python -m unittest discover -s tests -v
python -m leppo.experiment --steps 8192 --eval-slots 1000 --output results/demo
```

GPU 不是必需条件；本实现默认 CPU、2 个 PyTorch 线程。不需要 API 密钥或外部数据集。通用依赖列于 `requirements.txt`；CPU 机器推荐上面的分开安装方式，避免安装不需要的 CUDA 依赖。

较完整的实验（需要更长运行时间，仍需检查收敛）：

```bash
python -m leppo.experiment --steps 100000 --rollout 256 \
  --eval-slots 5000 --eval-seeds 101 102 103 104 105 \
  --algorithms leppo ppo no-gru --output results/full
# 从检查点重新评估（参数文件需与训练时一致）
python -m leppo.experiment --evaluate-only --config results/full/config.json \
  --output results/full --algorithms leppo ppo no-gru --eval-slots 5000
```

`--algorithms` 后不带名称时，只评估四个启发式基线。`--seed` 是训练种子，`--eval-seeds` 是独立测试种子。训练持续运行电池和队列，rollout 分段时用价值自举，不在每段重置电池。每次评估重置拓扑和电池，再连续运行指定时隙数，无预热剔除。请增加测试时长检查初始储能影响。

## 2. 文件与输出

- `leppo/environment.py`：路径损耗、导频复用、MMSE 方差、MRC/UatF SINR、能量收集、并行计算、电池、安全队列和动作修复。
- `leppo/policy.py`：能量历史 GRU、Logistic-Normal 动作、双 Critic、GAE、PPO 更新。
- `leppo/experiment.py`：训练、同随机场景评估、CSV/JSON 和绘图。
- `configs/default.json`：全部系统参数，单位采用 SI。
- `sweep.py`：参数敏感性和多训练种子实验入口。
- `tests/test_simulation.py`：闭式单用户公式、Monte Carlo 波束功率、能量守恒、队列与学习更新检查。

每个结果目录包含模型 `leppo.pt` / `ppo.pt`、`config.json`、训练日志 `train_*.csv`、逐时隙 `evaluation.csv`、汇总 `summary.json`、`comparison.png`、`metrics.png` 和 `training.png`。重复使用同一结果目录会覆盖对应输出，建议每个实验使用独立目录。模型加载仅用于自己生成且可信的检查点。

逐时隙输出包括每个 MD 的电量/队列/低电量事件，以及时延、收集/消耗/溢出能量、完成标志、动作修复率和原始动作违规程度。`summary.json` 中既有所有用户平均低储能比例，也有 `worst_user_low_fraction`；论文约束针对每个用户，不能只看平均值。

| 区域、AP/MD 高度 | 40×40 m²，3/1 m | 室内/近距离低功耗物联网；不假设宏蜂窝远距离供能 |
| 载波、带宽、噪声系数 | 915 MHz、1 MHz、7 dB | 低频 IoT 工作示例，不表示特定地区的部署许可 |

| 相干块 / 导频符号数 | 200 / 2 | 4 用户复用 2 条正交导频，显式产生污染 |
| 调度时隙 | 0.5 s | 多个相干块聚合的统计决策时隙，见下面说明 |
| 每 AP 发射 / MD 上行最大 / 导频功率 | 1 W / 1 mW / 1 mW | 能量供给较强、终端低发射功率的调试配置 |
| RF–DC 效率 | 0.5 | 文档使用的线性采能模型 |
| 阴影标准差、移动步长参数 | 4 dB、0.5 m/s | 阴影每回合固定，位置随时隙随机游走 |
| 任务数据、计算密度 | 5–15 kbit 均匀分布、300 cycles/bit | 低功耗传感任务，避免将手机级负载与微功率采能混用 |

| 电池容量、初始电量、安全阈值 | 0.5 mJ、60%、30% | 等效小储能单元，用来观察有限时间内的充放电行为 |

## 4. 数学模型对应与补充假设

记 βₘₖ 为大尺度功率增益，γₘₖ 为每根天线的 MMSE 估计方差，L 为每 AP 天线数，Sₖ 为同导频用户集合，σ² 为噪声功率。

1. **路径损耗**：嵌入式公式无法直接当作可执行公式导入；这里明确采用连续三斜率 close-in 模型：以 1 m 自由空间损耗为基准，1 m 内平坦，1–10 m 指数 2，10 m 外指数 3.5，叠加对数正态阴影。它保留三斜率结构，但不能声称与文档图中的具体常数逐字一致。距离使用三维米制。阴影每回合固定；移动采用周期边界位置随机游走，非轨迹跟踪模型。
2. **导频与 MMSE**：前 min(τp,K) 个用户作参考、其余选择最远参考用户的导频。γₘₖ=τp·Ppilot·βₘₖ²/(σ²+τp·Ppilot·Σⱼ∈Sₖ βₘⱼ)。默认所有用户导频功率相同。
3. **统计 CSI**：使用 Rayleigh 分块衰落的统计闭式量，不把瞬时小尺度样本代入已经取期望的 UatF 公式。Monte Carlo 测试独立检验 MRT 功率表达式。策略观察 β 和 γ。
4. **下行供能**：各 AP、用户的能量符号独立；瞬时单位范数 MRT。同导频估计方向相同，E|hₘₖᴴwₘⱼ|²=βₘₖ+(L−1)γₘₖ，其余为 βₘₖ。因此 Prf,k=PAP·Σₘ[βₘₖ+(L−1)γₘₖΣⱼ∈Sₖ ξₘⱼ]。不同 AP 的非相干功率相加，不错误引入跨 AP 相干平方增益。忽略噪声采能，保留通信噪声。
5. **上行 UatF SINR**：令 pⱼ=PUL·ηⱼ、Gₖ=Σₘγₘₖ。分子为 pₖL²Gₖ²；分母为 LΣₘγₘₖΣⱼpⱼβₘⱼ + L²Σⱼ∈Sₖ,j≠k pⱼ(Σₘγₘₖβₘⱼ/βₘₖ)² + σ²LGₖ。速率 B log₂(1+SINR)，所有 MD 同时活跃，采用文档的保守干扰模型。
6. **时隙解释**：0.5 s 为聚合调度周期，不宣称 1 MHz 下 200 个物理符号持续 0.5 s。用 τp/τc 作为聚合导频开销，剩余时间 Tdata=Tslot(1−τp/τc)。采能时间 αTdata、任务截止时间 (1−α)Tdata。闭式统计链路模型忽略块间细节。
7. **时延与能耗**：文档目标服务时延 `service_s=max(maxₖ DₖCₖaₖ₀/fₖ, maxₖ Dₖ(1−aₖ₀)/Rₖ + maxₘ ΣₖDₖCₖaₖₘ/Fₘ)`；上传同步结束后边缘计算，本地并行。另记录 `latency_s=导频时间+采能时间+service_s`，二者不能混淆。奖励的时延项采用文档的 **service_s**。MD 仅支付本地 κf²DCa₀ 与实际个人上传时间 pD(1−a₀)/R；不计算 AP 能耗、前传/结果回传、导频终端耗电和电路常耗，这些都是模型边界。
8. **电池与队列**：Bnext=min(Bmax,B+EH)−EC，先截断再消费，显式记录溢出。Qnext=max(0,Q+I[Bnext<εBmax]−δ)。文档引言/总结中的“能量赤字队列”与第四节安全队列有差异；本实现以第四节为准，不把二者混用。
9. **动作与修复**：α 映射到 [0.02,0.95]，η 到 (0,1)，每 AP 下行 ξ 行归一化，含本地选项的卸载向量归一化。用固定为零的参考 logit 消除 Softmax 冗余。高斯潜变量的 log-prob 用于 PPO 比率：固定的可逆映射 Jacobian 在新旧比率中抵消；后续确定性修复视作环境映射，始终对**原始潜变量**计算概率，不对修复后的动作伪造概率。熵奖励是潜高斯熵。
10. **可行域处理**：原动作满足能量与截止条件则直接执行，否则搜索 5 个 α×3 个 η×3 类卸载候选，并按时延与队列风险选可行项。这是有限候选可行性修复，不是精确欧氏投影或全局求解器，可能漏掉存在的可行解。无候选时记录 outage，仅采能、不接纳本时隙任务；不缩小任务后谎报全部完成。模型无任务积压队列；若需要任务不丢弃，应另加积压/重试模型。
11. **奖励说明**：rd=−V·service_s/Tslot；失败时额外处罚。re=−wq·mean[Q(I−δ)]+wb·mean[Bnext/Bmax]−wv·(原动作能量超限/Bmax+截止超限/Tslot)。它以安全队列的漂移上界构造奖励；文档图片奖励中仍有能量收支项，本代码选择与第四节安全约束一致的指标式队列项，并清楚区分这一实现选择。未任意截断 Q；大队列可能造成价值拟合困难，需要结合输出调参。

## 5. 对照、公平性与结论边界

- **LE-PPO**：GRU + 时延/能量双 Critic。
- **PPO**：同一观测、动作和总奖励，去掉 GRU、使用一个 Critic。
- **no-gru**：双 Critic 保留、只去掉时序编码，用于单因素消融。
- **random / fixed / local / greedy**：随机动作、固定均匀分配、全本地提案、自适应采能+70%卸载提案。

所有方法使用相同修复层；`local` 是全本地**提案**，能量不足时可能被修复为卸载，因此不能作为严格纯本地策略宣称。修复层使用队列风险，启发式基线也可能受益。必须联合报告动作修复率，不能把修复层收益全部归于学习网络。

每个测试 seed 对所有方法使用相同 AP/MD 初始位置、阴影、任务和移动随机序列，动作不影响外生随机数消耗。训练与测试 seed 分离。图中电池/队列轨迹来自第一个测试 seed；柱图是各 seed 的成功任务端到端时延均值和标准误，不是训练种子的置信区间。

务必同时报告任务失败率、成功任务时延、每用户低电量比例、最终 Q/T 与修复率。不要用失败时隙的占位 latency 当作真实任务完成时延；`summary.json` 的成功时延已剔除失败。有限时长内 Q/T 小或低储能比例小不能证明渐近稳定。默认短训练不保证收敛或满足 5% 目标；应使用多训练种子、足够长评估和单因素消融后再形成论文结论。
